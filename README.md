## Evidence and status discipline

Use explicit status labels where applicable:

- `LIVE`
- `PROTOTYPE`
- `RESEARCH`
- `CONCEPT`
- `HISTORICAL`
- `SUPERSEDED`
- `UNKNOWN`

A claim is not an implementation. A specification is not proof of execution. A commit proves that content was committed; it does not by itself prove that the described behaviour works.

Use the evidence chain:

`CLAIM → DOCUMENT → IMPLEMENTATION → OBSERVATION → RECORD → ATTESTATION → SEQ-07`

Record the relevant source, decision, version or commit, observed result, and any superseding decision. Mark unverified controls and behaviours as `UNKNOWN` or `NOT VERIFIED`, rather than implying success.

## Stewardship

The corpus is intended to support distributed stewardship, contributor onboarding, and succession rather than permanent founder control. Changes should preserve human authorship, decision provenance, customer privacy, and reversible review where practical.

Use focused branches and pull requests for substantive changes. Do not commit credentials, secrets, or private customer records. IKAI must not be represented as a face-identification, diagnosis, scoring, covert-surveillance, or hidden-profiling system.
