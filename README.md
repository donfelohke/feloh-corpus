## Technology constitution

WARENA and WARENA-governed IKAI infrastructure follow a native-first, libre-first, local-first, inspectable, reproducible and human-controlled policy.

- GNU is foundational, not an exclusive boundary; technically and ethically suitable free-software projects from other ecosystems may be adopted.
- Prefer GNU/Linux, Guile/Scheme, native interfaces, open standards, interoperability and recoverable local systems.
- JavaScript and web technologies are not approved as WARENA/IKAI application runtimes or architectural dependencies. Static documentation and publication are distinct.
- Avoid telemetry, tracking, DRM, tivoization, opaque control and default cloud dependency where they undermine user sovereignty.
- Evaluate existing scholarship, standards, projects and hardware before proposing new inventions. Reuse, adapt and credit creators.
- Preserve upstream licences, authorship, provenance and migration paths.

## Evidence and maturity

Use evidence labels consistently: **VERIFIED · CORROBORATED · DISPUTED · UNVERIFIED · INTERPRETATION · OPINION · TESTIMONY · PROPOSAL**.

Use maturity labels consistently: **LIVE · PROTOTYPE · RESEARCH · CONCEPT · HISTORICAL · SUPERSEDED · UNKNOWN**.

A file on `main` proves its presence on that branch only. A research note is not a prototype; a commit is not a deployment; a successful build is not runtime validation; a proposal is not an operational capability. Keep unknowns visible.
