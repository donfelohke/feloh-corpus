## 5. Technology policy summary

Native-first, libre-first, local-first. JavaScript and web technologies are prohibited as WARENA/IKAI application/runtime architecture; static publication and documentation are distinct. Desktop research is X11-first: X.Org initial compatibility, XLibre experiment, Gershwin case study, Guile-WM / WM-NG research. Wayland/dwl-guile remains secondary/experimental; Sway is comparison/recovery baseline.

Research programmes are not domains

## 7. Evidence and maturity

Claim labels: VERIFIED, CORROBORATED, DISPUTED, UNVERIFIED, INTERPRETATION, OPINION, TESTIMONY, PROPOSAL.  
Maturity labels: LIVE, PROTOTYPE, RESEARCH, CONCEPT, HISTORICAL, SUPERSEDED, UNKNOWN.

A repository file is not evidence of a running system. A commit is not a deployment. Mark unknowns rather than infer status.

## 8. Change control

Update shared constitutional records first, then dependent summaries. Preserve historical records with dated supersession notes. Do not duplicate specialist documents. Every implementation claim must identify the exact host/configuration, verification date, test/observation and recovery path where applicable.

## 9. Audit limitations

This map is a routing and ownership register, not a complete line-by-line audit or release certification. PR diffs, internal links, browser accessibility, deployed state, hardware and physical prototypes require separate verification. Unverified claims remain UNKNOWN.
