## 1. Purpose

Record the shared project boundaries for WARENA's expansion from conventional desktop research into spatial computing, immersive XR and optional AI. The detailed technical architecture belongs to WARENA; this document routes responsibilities and prevents duplicated or conflicting claims.

## 2. Canonical technical record

The canonical technical specification is [WARENA — Desktop, Spatial Computing, Immersive XR & Opt-in Intelligence Architecture (2026-11-20)](https://github.com/donfelohke/WARENA/blob/main/docs/SPATIAL-COMPUTING-XR-AI-ARCHITECTURE-2026-11-20.md).

Its historical foundations include:
- GNU/MAVERIK: application-aware spatial/graphics microkernel, callback-based access to application-owned data, and replaceable spatial/interaction services.
- DEVA3: distributed virtual environments, object behaviour and synchronization through subjectivity.
- OpenXR: native application/runtime interoperability API.
- Monado: Linux OpenXR runtime candidate.
- Native scene/graphics systems: rendering and scene representation, not substitutes for distributed world state.

The historical systems are architectural references. Source archaeology, exact version pairing, buildability and modern compatibility remain unverified.

## 4. Desktop and XR are distinct layers

The current WARENA desktop policy remains X11-first: X.Org initial compatibility baseline; XLibre compatibility experiment; Window Maker as a compact X11 window-manager reference; Gershwin as the GNUstep desktop case study; Guile-WM / WM-NG as Scheme-native window-management research. Wayland remains secondary/experimental; dwl-guile is experimental and Sway is a comparison/recovery baseline.

OpenXR is not a display server. Monado is not a desktop environment. An XR compositor is not automatically the X.Org server or a Wayland desktop compositor. Spatial windows and conventional desktop surfaces need explicit interoperability contracts.

## 5. Shared opt-in AI policy

AI is optional and disabled by default. No automatic model download, inference daemon, personal-file indexing, microphone/camera capture, telemetry, remote API or agent access is implied.

- Local inference is preferred; remote inference requires separate explicit opt-in.
- Context and tool access are scoped by purpose and permission.
- Agents receive no unrestricted shell, filesystem, network, device or credential authority.
- Read-only access is the initial permission tier.
- Consequential actions require human approval.
- Logs are inspectable and minimize content capture.
- Users can revoke access and disable services cleanly.
- Model output is an untrusted proposal, not verified evidence or authority.
- No identity, emotion, health, personality, ability or intent inference from appearance or movement.

Guile/Scheme may orchestrate policy and tools; inference implementation may remain a replaceable native component.

## Glass Terminal — cross-project design constitution — 2026-11-20

Glass Terminal is a shared UI/UX/XR research direction, not a fifth project, new repository, commercial brand or product release. It connects the existing project authorities without collapsing them.

| Concern | Authority |
|---|---|
| Native desktop, graphics, compositor/window management, XR runtime integration and reproducible packaging | WARENA |
| Reflective experience, physical mirror optics, participant authority, consent, privacy and memory semantics | IKAI |
| Embodied creative practice, movement notation, choreography, sound and performance authorship | GENJE |
| Shared terms, evidence, provenance, cross-domain governance and maturity labels | FELOH Corpus |
| Grounded services and all commercial transactions | NAKEBUSEN |

### Shared design principles

- Glass is a material and visual vocabulary, not an information hierarchy.
- Terminal means inspectability, composability, precision, programmability and human control.
- XR is an optional spatial modality; the conventional desktop remains independently useful.
- OpenXR is an application/runtime API, not a desktop display server or shell.
- Browser HTML/CSS may present public research but does not become WARENA or IKAI application architecture.
- Native-first, local-first and libre-first remain the system design constraints.
- Essential tasks must have non-gesture interaction paths.
- Reflection and movement remain participant-authored; no face identification, scoring, covert sensing or inferred personal labels.
- **ONLY NAKEBUSEN TRANSACTS.**
