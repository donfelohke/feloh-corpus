# Information-depth standard

**Version:** 2026-10-26  
**Purpose:** Shared quality bar for FELOH ecosystem documentation  
**Rule:** Depth means evidence and usefulness — not longer READMEs

## Seven layers (every domain repo)

| Layer | Required content |
|-------|------------------|
| **Orientation** | Purpose, scope, audience, terminology, links to corpus + siblings |
| **Foundations** | Principles, architecture, assumptions, decision rationale |
| **Evidence** | Sources, claim status, uncertainty, limitations |
| **Practice** | Workflows, templates, operating procedures |
| **Implementation** | Files, deps, config, reproducible steps (when real) |
| **Validation** | Tests, expected vs observed, open defects |
| **Stewardship** | Ownership, contribution, security, licence, succession |

## Status labels

**Maturity:** LIVE · PROTOTYPE · RESEARCH · CONCEPT · HISTORICAL · SUPERSEDED · UNKNOWN  
**Evidence:** VERIFIED · CORROBORATED · DISPUTED · UNVERIFIED · INTERPRETATION · OPINION · TESTIMONY · PROPOSAL

A commit is not an observation. A PR is not a deployment.

## Anti-patterns

- Copy-pasting the same long policy into every README  
- Claiming implementation without commands/results  
- Treating social posts as corpus without intake  
- Merging overlapping homepage PRs without reconciliation  

## Execution order

1. Reconcile open PRs  
2. Validate corpus terminology  
3. Specialist practice docs  
4. Gallery rights  
5. Profile + website alignment  
6. Link/CI checks  
7. Reviewable merges only after verification
