## 4. Technology constitution and capability

WARENA is governed by the [Technology Constitution (2026-11-17)](technology-policy-2026-11-17.md) and its specialist technical decision records. The shared direction is:

- Native-first, libre-first, local-first, inspectable, reproducible and user-controlled.
- GNU/Linux and GNU Guix; RDE as a configuration research layer; GNU Guile/Scheme as the preferred programmable systems layer.
- JavaScript is prohibited as a WARENA/IKAI application language, runtime, framework or architectural dependency.
- Web technologies are not the application architecture or runtime for WARENA/IKAI. Static publication and documentation are distinct from native system architecture.
- No telemetry, tracking, DRM, tivoization, cloud dependency or remote execution by default.
- Preserve upstream authorship, licences, provenance and a documented replacement path.

### 4.1 Desktop precedence

The current desktop research baseline is **X11-first**, not Wayland/Sway-first:
1. X.Org is the initial compatibility baseline.
2. XLibre is a drop-in compatibility experiment.
3. Gershwin is the X11 desktop-shell case study.
4. Guile-WM / WM-NG are window-management research.
5. Wayland is a secondary research track; dwl-guile is experimental.
6. Sway is a comparison and recovery baseline, not the primary desktop direction.

See [WARENA desktop architecture](https://github.com/donfelohke/WARENA/blob/main/docs/DESKTOP-ARCHITECTURE.md) and [desktop architecture decision](https://github.com/donfelohke/WARENA/blob/main/docs/desktop-stack-decision-2026-11.md). Hardware, host, configuration and deployment status must be evidenced separately.


### 4.2 Spatial computing, immersive XR and opt-in intelligence

WARENA's desktop architecture may be extended by independent spatial-computing and immersive-XR research layers. GNU/MAVERIK and DEVA3 are historical architecture references: MAVERIK informs application-aware spatial services; DEVA3 informs distributed virtual-environment state, object behaviour and synchronization. OpenXR is the native XR API candidate and Monado the Linux runtime candidate. These are research dispositions, not selected or deployed dependencies.

AI is optional and disabled by default. Model inference, context access, tool access and agent execution are separate capabilities requiring explicit, scoped authorization. Local inference is preferred; remote inference requires separate opt-in. No silent indexing, media capture, telemetry, unrestricted agent access or mandatory cloud dependency is permitted.

Detailed infrastructure architecture belongs in [WARENA's Spatial Computing, Immersive XR & Opt-in Intelligence Architecture (2026-11-20)](https://github.com/donfelohke/WARENA/blob/main/docs/SPATIAL-COMPUTING-XR-AI-ARCHITECTURE-2026-11-20.md). ## 6. Runtime and authority model

The canonical conceptual runtime is:

**OBSERVE → REFLECT → INTEND → COMPOSE → AUTHORIZE → ACT → EFFECT → REMEMBER**

Human authority is explicit. Observation does not imply consent to retain. Reflection does not imply judgement. Intention does not authorize action. Composition is a proposal until authorized. An agent or automated process may act only within an explicitly bounded permission. Effects must be observable and attributable. Memory is minimized, purpose-bound and governed by participant control.

This is a governance and architecture model, not proof that a runtime or agent exists.
