## Shared maintenance protocol

1. Change shared definitions in the Master Corpus first.
2. Update the owning specialist repository; link rather than duplicate detailed research.
3. Preserve upstream history, licence notices and creator attribution.
4. Separate source evidence, analysis, proposal, prototype, validation, release and live operation.
5. Keep unknowns visible; do not turn a missing record into a positive claim.
6. Use reviewable branches and pull requests; do not bypass branch protections.
7. Do not change Pages settings, publish private assets, expose customer data or alter payment flows through documentation maintenance.

## Status vocabulary

- **DOCUMENTED:** a source file or plan exists.
- **REVIEWED:** a named reviewer examined the specific artifact.
- **TESTED:** a reproducible test was run against a named revision and evidence retained.
- **DEPLOYED:** a deployment record identifies the target and commit.
- **LIVE-VERIFIED:** a post-deployment check confirmed the intended behaviour at a stated time.

These states are not interchangeable.
