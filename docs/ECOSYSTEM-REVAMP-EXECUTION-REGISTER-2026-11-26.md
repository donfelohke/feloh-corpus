## 6. Delivery protocol

For each repository:

1. Read its contributor/agent instructions and current source-of-record documents.
2. Inventory root files, documentation tree, workflows, tests, licence and upstream notices.
3. Identify contradictions, broken links, duplicate content, unsupported claims and missing validation.
4. Make focused changes on a dedicated branch.
5. Run available checks; record checks that cannot be run and why.
6. Open a pull request with scope, rationale, changed files, evidence and limitations.
7. Review the diff and automated results before merging.
8. Verify the resulting default-branch state and, where relevant, deployed behaviour.

No destructive cleanup or history rewrite. Historical records remain available and are marked as historical/superseded rather than silently deleted.
